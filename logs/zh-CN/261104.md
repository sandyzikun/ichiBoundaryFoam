## 对当前 IBM 路线的重新定位

当前原有算法通过 SDF 构造平滑或二值的固体体积分数，并将预测速度
向刚体速度约束：

$$
\mathbf u^*\leftarrow
\mathbf u^*+\chi_s(\mathbf u_b-\mathbf u^*).
$$

压力仍在包括虚构固体内部流体的整个背景域连续求解。标准压力投影
会再次改变受约束的速度，因此 MDF 重复执行：

```text
velocity forcing
-> flux reconstruction
-> continuous pressure-increment projection
-> correction of U, phi and p_rgh
-> slip evaluation
```

这一实现更适合称为 **diffuse-interface direct velocity forcing**。
广义上它仍属于在空间离散之后施加边界约束的 discrete/direct
forcing，但不等同于 Ye et al. 使用的 canonical sharp-interface
DF-IBM。

Ye et al. 的方法还包含：

* 明确的 fluid / forcing / solid cell 分类；
* forcing cells 上的二阶 Laplacian velocity reconstruction；
* 与 immersed boundary 相协调的离散通量处理；
* 由完整动量残差或重构表面应力得到的结构载荷；
* 两相工况中向虚构固体域延拓相分数，以避免错误密度梯度。

因此，问题不在于 SDF 本身，而在于 velocity forcing、pressure、flux、
VoF advection 和 load evaluation 尚未形成一个守恒且离散一致的整体。

## 压力处理的两条后续路线

今天的复审建议保留两种压力后端的设计空间：

* `continuousPressure`：压力在完整背景域连续求解，保留 PI 建议的
  路线和目前的稳定 baseline；
* `pressureDecoupled`：在 immersed surface 附近修改 pressure stencil
  或施加等价的 homogeneous Neumann condition，避免固体内部虚构
  压力直接影响流体侧压力。

这两种压力路线目前仍是后续架构规划。本日代码新增的是两种
`forcingMethod`，不能把 pressure backend 与 velocity-forcing backend
混为同一个选项。

## 可选的 `alpha.water` field extension

参考 Ye et al. 的两相 DF-IBM 做法，加入了可选的相分数延拓：

```foam
extendAlphaIntoSolid          false;
nAlphaExtensionLayers        5;
alphaExtensionWeightPower    2;
boundExtendedAlpha           true;
```

它从邻近非固体 cells 以距离加权方式逐层向固体内部延拓
`alpha.water`，目标是在 immersed surface 上近似满足：

$$
\frac{\partial\alpha}{\partial n}=0.
$$

延拓并不是只在“水侧”进行，而是在所有邻近固体结构的位置进行；固体
内部的延拓值只是用于稳定 IB 附近的密度和动量离散，不应计入真实
水体体积。

在当前 diffuse forcing + continuous pressure 的 Stokes II 对照中，
该选项没有改善结果：

| 设置 | 计算期间最大 `alpha.water` | 末时刻 slip [m/s] |
| --- | ---: | ---: |
| extension off | 1.39537 | 1.80252e-2 |
| extension on | 1.40420 | 3.77996e-2 |

因此默认值仍为 `false`。这个负结果并不否定 Ye et al. 的 extension，
而是说明单独把其中一个技巧接入当前 diffuse/continuous-pressure
组合，并不能替代其 sharp velocity reconstruction 与 flux coupling。

## 两种 `forcingMethod`

目前在 `constant/ichiBoundaryGeometry` 中可以选择：

```foam
ibm
{
    enabled                         true;
    forcingMethod                   diffuseVelocity;
    // forcingMethod                sharpReconstruction;

    transitionWidth                 0;
    sharpInterpolationLimit         1;
}
```

### `diffuseVelocity`

该后端完整保留原有实现。它使用 `immersedSolidFraction` 将预测速度与
刚体速度混合；当 `transitionWidth > 0` 时，forcing 分布在具有有限
厚度的 diffuse interface 内。

保留它的意义是：

* 保持此前算例与开发历史可复现；
* 作为低实现成本、稳定的 baseline；
* 用于判断后续 sharp reconstruction 是否真的改善边界位置、slip、
  载荷和两相守恒。

### `sharpReconstruction`

新增后端使用二值 SDF 分类：

* `cellType = 0`：普通流体 cell，不施加 forcing；
* `cellType = 1`：固体外侧第一层 forcing cell；
* `cellType = 2`：固体内部 cell，速度设为刚体速度。

forcing-layer target velocity 目前由 immersed-surface velocity 和更远
流体 neighbours 之间的有界线性 SDF 插值得到。它建立了向 Ye et al.
路线发展的 cell classification 与 reconstruction 入口，但仍只是第一版
实验性 sharp backend。

它目前尚未实现：

* Ye et al. 的二阶 Laplacian interpolation；
* immersed-face flux correction；
* processor boundaries 上的完整并行 reconstruction stencil；
* 在真实 SDF 投影点计算的旋转刚体表面速度；
* 可验证的 surface load reconstruction。

## sharp reconstruction 的一次失败与修订

第一版尝试在固体侧 ghost cell 中使用镜像外推：

```text
target = (1 + ratio) * U_body - ratio * U_fluid
```

该方法在当前连续压力与 MDF 组合中迅速放大速度，在约
`t = 0.0389 s` 时出现 `slip = O(10^59)` 和
`divergence = O(10^52)`，证明未经约束的 ghost extrapolation 不能直接
接入现有求解循环。

随后改为流体侧 forcing layer，并使用有界插值：

```text
ratio = min(d_forcing / d_fluid, sharpInterpolationLimit)
target = (1 - ratio) * U_body + ratio * U_fluid
```

该修订消除了短程测试中的指数放大。保留这次失败记录很重要：sharp
interface 并不只是把平滑 solid fraction 改成二值分类，还必须保证
reconstruction、pressure projection 和 flux correction 之间相容。

## 编译与短程验证

代码已在 OpenFOAM-com `v2312` 下重新编译。使用同一个两相
Stokes II 静止圆柱 case，对两个 forcing 后端运行至 `t = 0.1 s`：

| `forcingMethod` | forcing cells | 末时刻 max slip [m/s] | max divergence [1/s] |
| --- | ---: | ---: | ---: |
| `diffuseVelocity` | 128 | 5.52875e-5 | 6.89992e-11 |
| `sharpReconstruction` | 131 | 1.21547e-5 | 6.98791e-11 |

两条路径均正常结束。修订后的 sharp backend 在这次短程测试中没有
出现不稳定，且末时刻 slip 小于 diffuse baseline。

不过，这只是 smoke test，不是空间精度或物理正确性验证。当前不能由
这组数据推断 sharp backend 已优于 diffuse backend，更不能宣称已经
复现 Ye et al.。下一步仍需比较：

* 更长时间下的 `alpha.water` 超界与 accessible phase volume；
* body-fitted / diffuse / sharp 三者的速度、压力和结构载荷；
* 网格与时间步收敛性；
* forcing layer 上的 boundary residual，而不只是固体内部 slip；
* 串行与并行计算的一致性。

## 下一步建议

### 第一阶段：使 sharp velocity forcing 离散自洽

* 使用 SDF 法向和真实 boundary projection point 构造 image point；
* 实现并验证二阶 reconstruction；
* 同步处理 forcing 附近的 `phi` 与 VoF face flux；
* 补齐 processor boundary stencil；
* 为 sharp forcing layer 增加独立 residual diagnostics。

### 第二阶段：比较压力后端

* 保留当前 `continuousPressure` baseline；
* 实现可切换的 `pressureDecoupled` 原型；
* 比较 slip、divergence、pressure oscillation、相体积与计算成本；
* 不用无限增加 MDF correctors 掩盖 pressure coupling 问题。

### 第三阶段：载荷、运动结构与正式 benchmark

* 加入 forcing-volume load 的内部虚构流体惯性修正；
* 实现 surface-stress reconstruction 或 moving control volume load；
* 与同分辨率 body-fitted cylinder 比较力、力矩和相位；
* 为 fresh/dead cells 实现守恒的 `alpha/U/p` extension；
* 通过 prescribed translation/rotation 后，再接入双向 6DoF FSI。

综上，今天没有把现有实现包装成“已经成熟的两相 DF-IBM”，而是将
原有 diffuse baseline 与新的 sharp development path 明确分开。代码
架构现在允许二者直接对照，这为后续重写 forcing–flux coupling、比较
continuous/decoupled pressure，以及最终建立 monopile IBM benchmark
提供了更清楚的起点。
