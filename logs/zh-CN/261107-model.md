# `ichiBoundaryFoam` 单向耦合 IBM 技术画像

> 日期：2026-11-07  
> 用途：向另一个 ChatGPT instance 交接当前模型的真实技术路线、可选项、
> 与主流 IBM 的对应关系，以及尚未实现的部分。  
> 依据：当前 `ichiBoundaryFoam` 源码、算例字典和公开原始文献。本文不把
> roadmap 中的计划误写成已经实现的功能。

## 一句话摘要

当前模型是一个建立在 `interFoam`-like algebraic VoF 求解器上的、
**单向耦合、SDF 几何、cell-centred discrete direct forcing IBM**。
默认采用 `diffuseVelocity` 固体域速度强制和 continuous pressure；启用
MDF 时，默认在预测速度上重复 forcing，且不在每一轮中重复解算 Poisson
方程。它不是 Peskin
意义下的 continuous-forcing IBM，也不是成熟的 ghost-cell、cut-cell 或
Ye-type sharp-interface IBM。

结构可以概括为：

```text
prescribed rigid-body motion
            ↓
analytic SDF of a capped cylinder
            ↓
cell classification / solid fraction
            ↓
direct correction of the velocity predictor
            ↓
optional MDF iterations
            ↓
regular interFoam pressure projection and VoF evolution
```

目前物体运动由用户预设，流体载荷不会反馈给运动方程，所以这是
one-way WSI，而不是 two-way FSI。

## 多个分类维度中的位置

| 分类维度 | 当前默认路线 | 可选或未来路线 |
|---|---|---|
| forcing 写入层级 | discrete forcing | continuous forcing 未实现 |
| 边界表示 | grid-scale / diffuse-like solid-domain forcing | 实验性 `sharpReconstruction` |
| 几何表示 | analytic SDF，cell-centred | STL/三角面、Lagrangian markers 未实现 |
| 强制方式 | explicit direct velocity correction | monolithic implicit constraint 未实现 |
| 迭代 | MDF 源码默认关闭；启用后采用 predictor-level MDF | 可启用 pressure-projected MDF |
| 压力 | full-domain continuous pressure | `pressureDecoupled` 尚未实现 |
| 两相界面 | algebraic VoF/MULES | geometric VoF 未实现 |
| VoF–固体交会 | 默认不扩展 `alpha.water` | 可启用 Ye-inspired field extension |
| 固体运动 | prescribed static/constant/harmonic 6DoF | load-driven 6DoF 未实现 |
| 耦合方向 | solid motion → fluid | fluid load → solid motion 未实现 |
| 湍流 | 沿用 OpenFOAM turbulence model | IBM wall function 未实现 |
| 载荷 | forcing-volume integral，preliminary | 可靠表面压力/剪切积分未实现 |

Mittal 与 Iaccarino 将 IBM 广义分成 continuous forcing 和 discrete
forcing；这里的分类依据是强制项在连续方程层面还是离散方程层面构造，
并不等价于 diffuse/sharp interface
（[Mittal & Iaccarino, 2005](https://doi.org/10.1146/annurev.fluid.37.061903.175743)）。

## 1. Continuous forcing 还是 discrete forcing？

### 当前选择：discrete direct forcing

当前程序先形成离散预测速度 `HbyA`，再直接计算使其逼近刚体表面速度所需
的速度修正：

$$
\Delta\boldsymbol{U}
=
\chi_s
\left(
\boldsymbol{U}_b-\boldsymbol{U}^{*}
\right),
$$

其中 $\chi_s$ 由 SDF 生成的 `immersedSolidFraction` 表示。修正随后加入
预测速度，并以

$$
\boldsymbol{a}_{IB}=\frac{\Delta\boldsymbol{U}}{\Delta t}
$$

记录等效 IBM 加速度。这是离散层面的 algebraic direct forcing，不是先在
连续 N–S 方程中定义一个平滑力模型、再统一离散。

### 与主流方案的关系

* Peskin 原始路线以 Eulerian 流体和 Lagrangian 结构为基础，通过
  regularized delta kernel 插值速度并扩散结构力，通常归入 continuous、
  diffuse-interface 家族。当前代码没有 Lagrangian surface markers，也
  没有 regularized delta kernel，因此不属于这一支。
* Uhlmann 将 regularized-delta 传递与直接求取流固作用力结合，是经典的
  direct-forcing/diffuse-interface 粒子 IBM
  （[Uhlmann, 2005](https://www.sciencedirect.com/science/article/pii/S0021999105001385)）。
  当前代码同样是 direct forcing，但使用 cell-centred SDF/solid fraction，
  而不是表面 marker 与 delta kernel。
* Fadlun、ghost-cell 和 immersed-interface 一类方案在离散 stencil 上直接
  重构边界条件，通常形成 sharp interface。当前实验性
  `sharpReconstruction` 在思想上更接近这支，但能力还没有达到成熟
  ghost-cell 方法的程度。

## 2. Diffuse interface 还是 sharp interface？

### 默认 `diffuseVelocity` 的真实含义

默认运行配置为：

```foam
forcingMethod      diffuseVelocity;
transitionWidth    0;
```

`diffuseVelocity` 用 solid fraction 混合目标速度和预测速度。当
`transitionWidth>0` 时，SDF 两侧一个有限厚度内采用平滑 Heaviside-like
过渡，确实是 diffuse interface。

但默认 `transitionWidth=0` 时，solid fraction 是按 cell centre 的 SDF
正负二值分类。这使分类不再平滑，却仍然**不能称为严格 sharp interface**：

* 边界位置被量化到背景 cell；
* no-slip 没有在 SDF 与网格线/面真实交点上精确施加；
* 没有 ghost value、jump condition 或 cut-face flux；
* 几何误差和边界厚度仍是 grid-scale 的。

因此，默认路线最准确的称呼是：

> cell-centred solid-domain direct forcing with a grid-scale interface

它比平滑 delta forcing 更“硬”，但不等于主流 sharp-interface IBM。

### 实验性 `sharpReconstruction`

运行时可改为：

```foam
forcingMethod            sharpReconstruction;
sharpInterpolationLimit  1;
```

程序会把 solid cells 设为刚体速度，并在邻接固体的 fluid forcing cells 中，
利用 SDF 距离、刚体速度和外侧流体 cell 速度作局部 inverse-distance
reconstruction。

它目前只是 sharp-inspired prototype：

* 没有显式求取 surface–grid intersection；
* 没有沿法向构造正规的 image/ghost point；
* 没有为 pressure、VoF、turbulence quantities 建立配套 sharp stencil；
* 没有 cut-cell 几何守恒；
* 源码本身也将其标记为 experimental。

Mittal 等人的成熟 sharp-interface 方法在边界真实位置施加条件，避免将
forcing 非物理地扩散到流体区域，并特别处理 mass conservation 和压力
振荡；这是当前 prototype 尚未达到的标准
（[Mittal et al., 2008](https://doi.org/10.1016/j.jcp.2008.01.028)）。

## 3. 几何：SDF、surface markers 还是 cut cells？

当前只支持解析的 `cappedCylinder`：

```foam
geometry
{
    type               cappedCylinder;
    centre             (10 0 0.6);
    radius             0.045;
    length             1.2;
    referenceRotation  (0 0 0);
}
```

每个时间步在 cell centre 和 boundary-face centre 计算：

* `signedDistance`；
* `immersedSurfaceNormal`；
* `immersedSurfaceVelocity`。

SDF 小于零表示固体内部，大于零表示外部。优点是圆柱运动时无需重新网格，
法向和距离计算便宜、确定且光滑。限制是：

* 目前不能直接读取任意 STL/CAD；
* 没有离散三角面 immersed surface；
* 没有 Lagrangian markers；
* 没有真实 cut-face area/volume，因此不是 conservative cut-cell method。

与 Uhlmann/Constant 一类 marker IBM 相比，我们省去了 marker–Eulerian
插值与力扩散，但也失去了明确的表面离散与成熟的任意几何支持。

## 4. Explicit、MDF 还是 monolithic implicit constraint？

### 启用 MDF 后的默认算法：预测速度上的 explicit MDF

`multiDirectForcing=true` 时，默认在预测速度 `HbyA` 上反复施加直接速度
修正，然后只调用原本的 `p_rgh` pressure projection 一次：

```text
momentum predictor
    → direct forcing × N
    → ordinary pressure projection
```

这符合经典 MDF 的主要思想：重复 boundary interpolation/forcing 来减小
no-slip error，但不必每轮都重新求解 Poisson 方程。Wang 等人的 combined
MDF 是这一类方法的重要来源
（[Wang et al., 2008](https://doi.org/10.1016/J.IJMULTIPHASEFLOW.2007.10.004)）。

它仍是 sequential/explicit coupling：pressure projection 可能重新改变边界
附近速度，因此最终 slip 不保证严格为零。

### 可选：每轮 MDF 后进行 pressure projection

编译时设定：

```bash
make ENABLE_MDF_PRESSURE_PROJECTION=1
```

则恢复：

```text
[direct forcing → global pressure correction] × N
```

这是一种 alternating constrained projection，同时追逐 no-slip 和
divergence-free。它并非没有文献依据：Constant 等人在 OpenFOAM/PISO 中
也通过 IBM 与 pressure correction 的 sub-iteration 同时施加固体约束和
无散约束
（[Constant et al., 2017](https://arxiv.org/abs/1609.04364)）。

但当前实现每轮都求解全域 `immersedPressureCorrection`，计算成本很高。
它应作为严格/保守对照，而不是默认 baseline。

### 尚未实现：monolithic constraint solve

Taira–Colonius projection IBM 和 Kallemov 等人的方法把 pressure 与 IB
force 同时视为 Lagrange multipliers，直接求解 coupled saddle-point
system，而不是交替修补两个约束
（[Taira & Colonius, 2007](https://www.sciencedirect.com/science/article/pii/S0021999107001234)，
[Kallemov et al., 2016](https://msp.org/camcos/2016/11-1/camcos-v11-n1-p04-p.pdf)）。
这类方法约束更系统，但需要 Schur-complement/preconditioner 等明显更大的
线性代数重构，当前程序没有实现。

## 5. 压力路线

### 已实现：continuous pressure

`p_rgh` 仍在整个背景域上求解。immersed surface 不被当作 pressure
equation 的内部边界，固体内外也没有人为压力跳跃或断开 stencil。这正是
PI 所建议的路线。

优点：

* 实现简单，保留 OpenFOAM 原压力矩阵结构；
* 固体运动时不必不断重建 pressure boundary topology；
* 与 predictor-level MDF 配合时附加压力成本较低。

风险：

* 固体内部的非物理解仍参与 pressure stencil；
* immersed surface 上的真实 pressure Neumann condition 没有显式施加；
* 近壁压力与压力载荷的局部精度需要 body-fitted benchmark 验证。

### 尚未实现：`pressureDecoupled`

历史笔记中曾规划 `pressureDecoupled`，但当前源码不存在相应 runtime key、
preprocessor branch 或 pressure stencil implementation。它只是 roadmap。

成熟 sharp-interface/ghost-cell/cut-cell 方法通常会在 IB 附近显式处理
pressure boundary condition、jump/stencil 或 cut-face flux。不能把当前
continuous-pressure solver 描述成已经具备这些能力。

## 6. 单向还是双向流固耦合？

当前支持三种 prescribed motion：

```foam
motion { type static; }
motion { type constant6DoF; ... }
motion { type harmonic6DoF; ... }
```

`constant6DoF` 可指定恒定平移速度和转动角速度；`harmonic6DoF` 可分别指定
三个平移和三个旋转分量的 amplitude、frequency 与 phase。

刚体运动决定

$$
\boldsymbol{U}_b
=
\boldsymbol{V}
+
\boldsymbol{\Omega}
\times
(\boldsymbol{x}-\boldsymbol{x}_c),
$$

并影响 SDF 和流体速度；但是流体载荷不会更新 $\boldsymbol{V}$、
$\boldsymbol{\Omega}$ 或刚体姿态。

程序会以施加强制的体积分给出 preliminary force/moment：

$$
\boldsymbol{F}_{body}
=
-\sum_c \rho_c V_c\boldsymbol{a}_{IB,c},
$$

但它目前只用于诊断，没有进入质量、惯量和 6DoF 动力学方程，也尚未证明
与表面 pressure + viscous traction 积分等价。因此准确称呼是：

> prescribed-motion one-way WSI with preliminary load diagnostics

## 7. 两相 VoF 与 IBM 的结合

### 基础 VoF

求解器复用 OpenFOAM-com v2312 `interFoam` 的 algebraic VoF/MULES 路线，
包括 interface compression、`alpha.water` sub-cycling、混合密度/黏度、
表面张力、重力和 wave boundary models。IBM 没有把它改成 geometric VoF。

每个 PIMPLE outer iteration 中的大致次序是：

```text
update SDF and cell classification
    → solve alpha.water
    → optional alpha extension into solid
    → update mixture
    → momentum / IBM forcing / pressure correction
```

### 默认：不作 `alpha.water` extension

```foam
extendAlphaIntoSolid  false;
```

这避免 extension 自身改变全局 phase volume，但当自由液面与 immersed
surface 相交时，固体内部未定义/非物理的 $\alpha$ 与密度可能污染
$\nabla\rho$ 和浮力项。

### 可选：Ye-inspired field extension

```foam
extendAlphaIntoSolid          true;
nAlphaExtensionLayers        5;
alphaExtensionWeightPower    2;
boundExtendedAlpha           true;
```

程序从外部流体 cell 开始，逐层用 inverse-distance weights 将
`alpha.water` 延拓进固体。这与 Ye 等人 2020 年 air–water IBM 中的 dilation/
field-extension 思路高度接近：其目的不是让固体变成真实流体，而是间接
实现近似 homogeneous Neumann condition，避免高密度比下错误的
density gradient
（[Ye et al., 2020](https://doi.org/10.3390/jmse8100809)）。

两者仍有重要差异：

* Ye 使用完整 sharp discrete-forcing framework；当前默认是 cell-centred
  diffuse-like velocity forcing；
* Ye 配有更系统的 IB interpolation 与 turbulence treatment；
* 当前 extension 是可选实验功能，早期测试中并未自动改善所有
  `alpha.water` overshoot，因此不能单独视为两相 IBM 已验证。

## 8. 湍流处理

`ichiBoundaryFoam` 可以调用 OpenFOAM 的 laminar、$k$-$\varepsilon$、
$k$-$\omega$ SST 等 transport/turbulence models，但当前 IBM 只直接强制
速度：

* 没有对 `k`、`omega`、`epsilon` 设置 immersed wall conditions；
* 没有 IBM wall distance；
* 没有专用 wall function；
* 没有验证 immersed-wall shear stress。

Ye 的单相 turbulent IBM 以及后续两相工作配合了专门的 turbulence/wall
treatment。因此，“求解器能启动 $k$-$\omega$ SST”不等于“IBM 湍流近壁
模型已经物理正确”
（[Ye et al., 2020, turbulent-flow IBM](https://doi.org/10.1177/1475090220927245)）。

## 9. 编译期选项

当前 `Makefile` 的选项如下：

| 选项 | 默认 | 作用 |
|---|---:|---|
| `ENABLE_DIRECT_FORCING` | `1` | 编译 direct-forcing backend |
| `PURE_INTERFOAM` | `0` | `1` 时走原生 interFoam regression path |
| `ENABLE_SLIP_SAMPLING` | `0` | 编译详细 immersed-surface-band slip 诊断 |
| `ENABLE_MDF_PRESSURE_PROJECTION` | `0` | 每轮 MDF 后额外求全域压力修正 |

默认构建：

```bash
make
```

启用详细 slip fields/statistics：

```bash
make ENABLE_SLIP_SAMPLING=1
```

恢复昂贵的 pressure-projected MDF：

```bash
make ENABLE_MDF_PRESSURE_PROJECTION=1
```

生成 pure-`interFoam` regression binary：

```bash
make pure-interfoam
```

这些选项会改变 executable；运行中的 binary 不应被原地重新编译覆盖。

## 10. 运行时选项及源码默认值

以下条目位于 `constant/ichiBoundaryGeometry` 的 `ibm` dictionary：

| key | 源码默认值 | 说明 |
|---|---:|---|
| `enabled` | `false` | 是否启用 IBM |
| `forcingMethod` | `diffuseVelocity` | `diffuseVelocity` 或实验性 `sharpReconstruction` |
| `transitionWidth` | `0` | diffuse solid fraction 的半过渡宽度 |
| `sharpInterpolationLimit` | `1` | sharp reconstruction 中的插值比例上限 |
| `multiDirectForcing` | `false` | 是否启用 MDF |
| `nMultiDirectForcingCorrectors` | `1` | MDF 追加 correctors 数量，至少为 1 |
| `slipTolerance` | `0` | 大于零时允许 MDF 提前退出 |
| `extendAlphaIntoSolid` | `false` | 是否延拓 `alpha.water` |
| `nAlphaExtensionLayers` | `5` | 延拓层数 |
| `alphaExtensionWeightPower` | `2` | inverse-distance exponent |
| `boundExtendedAlpha` | `true` | 是否把延拓结果限制在 $[0,1]$ |

若编译了 `ENABLE_SLIP_SAMPLING=1`，还可设置：

| key | 源码默认值 | 说明 |
|---|---:|---|
| `slipSamplingBandWidth` | `0` | SDF 两侧采样带宽；0 表示不作详细采样 |
| `slipLiquidThreshold` | `0.5` | 区分 liquid/gas samples 的 alpha 阈值 |

几何和运动字典还支持：

* `fieldName`，默认 `signedDistance`；
* `geometry.type=cappedCylinder`，这是当前唯一几何；
* `motion.type=static|constant6DoF|harmonic6DoF`；
* `referenceTime`、translation/rotation velocity；
* harmonic amplitude、frequency 和 phase。

## 11. 与几条主流路线的对照

### Peskin-type continuous/diffuse IBM

相同点：都在非贴体背景网格上表达固体影响。

不同点：Peskin-type 使用 Lagrangian structure、delta interpolation 和
force spreading；当前代码使用解析 SDF 与 cell-centred algebraic velocity
correction。当前路线更容易嵌入现有 finite-volume solver，但没有该体系
成熟的离散伴随插值/扩散结构。

### Uhlmann-type direct forcing

相同点：直接依据目标边界速度求 forcing，可配合 MDF。

不同点：Uhlmann 在表面 markers 和 Eulerian grid 之间用 regularized delta
传递；当前程序在 solid/forcing cells 上直接操作。因此当前模型不应被称为
Uhlmann 方法的逐项复现。

### Ghost-cell / immersed-interface sharp IBM

相同点：实验性 `sharpReconstruction` 都试图从界面几何和外部流体值重构
近壁速度。

不同点：成熟方法在真实 boundary intersection 上处理 velocity/pressure
conditions，并构建专门 stencil；当前版本没有 ghost/image point，也没有
pressure jump/stencil，因此仍相距较远。

### Conservative cut-cell

相同点：都能在固定背景网格表示复杂几何。

不同点：cut-cell 对被几何切割的 control volumes/faces 重新计算守恒通量；
当前代码不改变 mesh topology 或 face area，只用 body force/velocity
correction。因此当前路线实现简单、运动方便，但局部质量/动量守恒不具备
cut-cell 的几何保证。

### Constant et al. OpenFOAM discrete IBM

相同点：OpenFOAM finite-volume/PISO(PIMPLE) 框架、discrete forcing，并可
在 IBM 与压力修正之间 sub-iterate。

不同点：当前默认已经把这类压力 sub-iteration 关闭，仅将其保留为编译期
严格对照；当前几何和 forcing 也采用自己的 SDF/cell-centred 实现。

### Ye et al. air–water sharp discrete IBM

相同点：两相 VoF、移动刚体、discrete forcing，并提供 inverse-distance
`alpha` extension。

不同点：Ye 路线更接近完整 sharp-interface reconstruction，并包含面向
RANS/ship hydrodynamics 的近壁处理；当前只有实验性 sharp velocity
reconstruction，pressure、turbulence 与 surface load 尚未形成配套的
sharp-interface 系统。

## 12. 当前默认 baseline 的准确表述

若使用常见 IBM 算例设置：

```foam
enabled                         true;
forcingMethod                   diffuseVelocity;
transitionWidth                 0;
multiDirectForcing              true;
nMultiDirectForcingCorrectors   4;
slipTolerance                   1e-5;
extendAlphaIntoSolid            false;
```

并以默认 Makefile 编译，则应描述为：

> `ichiBoundaryFoam` currently uses a one-way-coupled,
> SDF-based, cell-centred discrete direct-forcing IBM. The rigid-body
> kinematics are prescribed. Multi-direct forcing is applied to the
> velocity predictor, followed by the regular full-domain continuous-
> pressure projection. The default interface treatment is grid-scale
> solid-domain forcing rather than a formally sharp ghost-cell or
> cut-cell scheme. Algebraic VoF is used for the air–water interface,
> with an optional Ye-inspired phase-fraction extension into the solid.

## 13. 当前不能声称的能力

为了避免后续讨论误判，当前不能声称：

* 已经实现 two-way 6DoF FSI；
* 已经实现正式的 Ye-type sharp-interface IBM；
* 已经实现 `pressureDecoupled` backend；
* 已经实现 ghost-cell、immersed-interface 或 conservative cut-cell；
* 已经实现任意 STL/CAD geometry；
* 已经验证 IBM wall shear、wall function 或 RANS near-wall accuracy；
* preliminary forcing-volume load 已等价于可靠的表面受力；
* `alpha` extension 已解决两相 IBM 的所有 boundedness/mass 问题；
* 当前 IBM 已经可以替代 body-fitted monopile benchmark。

## 14. 推荐的近期比较矩阵

在继续增加功能之前，最小但有判别力的比较为：

| 比较 | 目的 |
|---|---|
| body-fitted vs IBM | 确认速度、压力、载荷和相位误差 |
| MDF 1/2/4/8 | 建立 slip–cost 曲线 |
| predictor MDF vs pressure-projected MDF | 判断额外 Poisson 的真实收益 |
| `diffuseVelocity` vs `sharpReconstruction` | 判断实验性重构是否改善局部误差 |
| alpha extension off/on | 检查交会区密度梯度和 phase-volume 误差 |
| laminar vs $k$-$\omega$ SST | 暴露缺失 IBM wall treatment 的影响 |
| static vs prescribed motion | 检查 covered/uncovered cells 和几何更新 |

每组至少记录：

* surface-band normal/tangential/max/RMS slip；
* $\max|\nabla\cdot\boldsymbol{U}|$；
* `alpha.water` min/max 和 accessible phase volume；
* force/moment 与 body-fitted reference；
* pressure iterations、wall time 和 memory；
* 自由液面相位与幅值。

## 15. 最终判断

当前路线没有偏离 IBM 大类：它位于 discrete direct forcing 家族中，
continuous-pressure 和 predictor MDF 也都有清楚的数值动机。但它是一套
处于开发期的混合路线：几何采用 SDF，默认边界为 cell-centred
diffuse-like forcing，另有实验性 sharp reconstruction；两相部分借鉴 Ye
的 alpha extension，但尚未实现其完整 sharp/turbulence framework。

它最适合现在承担两项任务：

1. 作为可控、容易修改的 IBM research prototype；
2. 与 body-fitted monopile 建立逐层 benchmark。

在 surface slip、pressure/load、phase conservation 和 turbulence wall
treatment 通过验证前，不应把它称作 production-ready offshore WSI solver。
